# 評価用セル定義(LLM判定用)

LLMの評価(evals)において、入力側の条件と期待される出力(正解ラベル)を分類するためのマトリクスです。下記の全6セルで構成されます。

| # | status | 入力側の軸 | 正解のmissing | セルを独立させている理由・備考 |
|---|---|---|---|---|
| **1** | 要対応 | 情報が揃っており、対応が必要な条件を満たしている | `[]` | アラート対象。深刻度ごとの分岐はここに含めず、後続のコードで処理する。 |
| **2** | 要確認 | 正解の不足キーが1つ(※セル6を除く) | 1件 | 単純なパラメータ・設定値の漏れ。 |
| **3** | 要確認 | 正解の不足キーが2つ以上(※セル6を除く) | 2件以上 | 複数情報の同時不足。 |
| **4** | 対応不要 | 情報が揃っている(脆弱性の影響を受けない等) | `[]` | 影響を受けないバージョン等。 |
| **5** | 対応不要 | 欠けているが、発動の必要条件が崩れている | `[]` | 欠けた情報に引きずられて「要確認」に倒れやすいため、失敗の仕方を観測する目的でセル4と区別する。 |
| **6** | 要確認 | **CVEの対象のコンポーネントが、profileのcomponentsに存在しない** | そのコンポーネントが導入されているかを問うキーが含まれる | **対応不要へ倒れるリスクを観測するため。** <br>失敗時に最も危険な側(対応不要)へ倒れるため独立。 **※判定優先度: セル2・3より優先して適用する。** |

## セル適用およびラベル付けのルール
* **セル6(未登録コンポーネント)の優先順位と正解ラベル**
  * **優先判定**: 未登録のコンポーネントの入力は、セル2や3の条件よりも優先して **セル6** に割り当てる(セル2・3の対象から除外)。
  * **正解定義**: そのコンポーネントが導入されているかを問うキーが含まれていること(キー名の表記は問わない)
